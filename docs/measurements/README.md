# 측정 기록

계획서 §9의 핵심 규칙: **숫자 없으면 개선이 아니다.**
마일스톤마다 `Mx.md`에 **변경 전 수치 → 변경 내용 → 변경 후 수치 → 해석**을 남긴다.
각 마일스톤의 "해석" 한 문단이 그대로  답변이 된다. 효과 없던 시도도 기록한다.

## 양식 (각 Mx.md)

```markdown
# Mx — <제목>

## 환경
- 하드웨어 / JVM 옵션 / 동시 디바이스 수 / 부하 도구(k6 시나리오)

## 일부러 만든 문제
- (해당 시) 무엇을 의도적으로 깨뜨렸나

## Before
- p95 / p99 / 처리량(req/s, rows/s) / 에러율 / 기타 지표
- (Grafana 스크린샷 첨부)

## 변경 내용
- 무엇을 어떻게 바꿨나

## After
- 같은 지표 재측정

## 해석
- 왜 좋아졌나 / 한계 / 다음 병목 (=  답변)
```
