# 0005 — 시뮬레이터: 같은 앱 + 프로파일

- 상태: 확정
- 일자: 2026-06-19

## 결정
폰 시뮬레이터를 별도 모듈/실행체로 빼지 않고 **같은 앱의 `app.simulator` 패키지**에 두고,
`simulator` 스프링 프로파일로 켠다.

```
./gradlew bootRun --args='--spring.profiles.active=simulator'
```

## 근거
- 단일 모듈 결정([0002](0002-single-module-with-archunit.md))과 일관. 도메인 모델·내부 API 재사용이 쉽다.
- **부하 주력은 k6**(계획서[저장소 밖 초기 기획 문서] §6, 별도 프로세스)다. 시뮬레이터는 "현실적 움직임 패턴"(보행자 random walk, 신호 끊김, 배터리 감소) 담당이라 JVM 격리 압박이 작다.
- Java 21 가상 스레드로 폰 1대 = 가상 스레드 1개.

## 기각된 대안
- **별도 모듈/실행 jar**: 더 현실적(외부 디바이스처럼 HTTP/Kafka로만 통신)이지만 멀티모듈이 사실상 전제되고 초기 비용이 크다. 측정 격리 이득은 k6가 이미 제공.

## 후속
- 필요해지면 `app.simulator`를 모듈/독립 jar로 추출(패키지 경계 유지 시 소규모 작업).
